Version 1.3.7 upgrades LG webOS to the deployed device API v2. An installation generates a random 12-character hexadecimal display code and a private 256-bit token, persists them before registration, and registers as alaa_player (panel label Alaa Player). Legacy code-only identities are not reused; the new pending device must be activated in the panel. There is no code-only credential fallback.

Identity and cached configuration/catalog records are encrypted with AES-GCM using a nonextractable Web Crypto key persisted in IndexedDB. This is browser-origin storage, not a claim of hardware-backed key protection against an OS-level attacker. If Web Crypto or durable IndexedDB storage is unavailable, pairing fails closed. Existing plaintext catalog storage is cleared when the new identity is first created.

Startup begins secure panel refresh before provider synchronization, alongside hydration of a valid policy-scoped encrypted snapshot. A temporary panel failure may use the last encrypted active config only while its expiry has not passed. Authoritative inactive, pending, expired, unauthorized, or registration_expired responses remove remote provider content and stop playback. Network errors and rate limits do not clear known category policy. The rate limit retry time is honored; normal refresh is on open/foreground and at the existing 30-minute cadence.

Xtream catalogs are requested category-first with category_id. Hidden IDs are exact strings scoped to playlist and media. Explicit malformed/unsupported policy preserves a previous policy for the same provider; without one, catalog requests are deferred. Legacy responses without all category fields establish empty policy. Membership is validated on every returned row, including providers that return rows outside the requested category. Missing membership is discarded; shared items with any known hidden membership are discarded. M3U does not support Xtream category hiding.

Policy changes cancel provider requests, invalidate old jobs and artwork, clear derived projections, purge encrypted catalog records, and retain only permitted in-memory items. Favorites/history retain opaque IDs only. Newly unhidden categories do not trigger bulk stream prefetch. Categories are enumerated in the background, while contents/artwork are loaded when requested by the UI. Initial Home still loads its existing first visible movie/series category. No fallback to an unfiltered catalog endpoint is used.

Tests use Chromium 87 and mocked providers, including plain HTTP, offline cache, malformed policy cold restart, identity persistence, encrypted storage, lazy unhide, expiry and request tracing. This is not real LG hardware or live customer-provider validation. Providers ignoring category_id may transfer hidden rows inside a response; the app filters those rows before persistence or use and cannot guarantee transfer savings for such providers. No TV speed measurement is claimed.
